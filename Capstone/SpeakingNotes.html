🎤 Valza — Speaking Notes 1.5–2 min

"As Tech Lead, I owned the architecture and security design. I wrote the permission matrix — our single source of truth for what each role can do — and seven Architecture Decision Records that explain why we chose JWT in httpOnly cookies, integer PKs with authorization checks, and dual validation in Pydantic and PostgreSQL.

On the backend I designed the ticket lifecycle state machine, RBAC enforcement via require_roles(), and Pydantic schemas that whitelist fields so clients cannot escalate privileges. In Sprint 3 I added pagination, sorting, and dashboard metrics APIs.

Everything else in the project connects to these rules: Paulina implements them in the database, the frontend team builds UI that respects them, and Lis's CI tests verify them on every PR."
  • Demo point: Show permission matrix → then live 403 IDOR demo
  • If asked "why httpOnly cookies?": ADR-001 — JS cannot read them, XSS-safe
  • If asked "why integer IDs?": ADR-003 — auth is the guard, not ID obscurity

🎤 Paulina — Speaking Notes 1.5–2 min

"I was responsible for the backend engine and data layer. I gatekeep all database changes — models and Alembic migrations — so five developers don't create conflicting schema changes.

I built the initial PostgreSQL schema with CHECK constraints for status, priority, and role, then implemented the core API: auth with JWT cookies, role-scoped ticket listing, ticket creation where requester_id always comes from the token, and file uploads to MinIO.

In Sprint 3 I added search and filtering with parameterized queries, and fixed mass-assignment vulnerabilities by forbidding extra fields on auth schemas. I also integrated the frontend API client with automatic token refresh on 401.

My work connects to Valza's security design on one side and Egzona's UI on the other — the frontend never touches the database, only my REST API."
  • Demo point: Show Swagger /docs → POST /tickets → point out requester_id NOT in body
  • If asked about migrations: ADR-005 — Alembic only, one at a time, rollback with downgrade
  • If asked about attachments: Metadata in Postgres, binary in MinIO, presigned URL download

🎤 Egzona — Speaking Notes 1.5–2 min

"As Frontend Lead, I built what the user actually sees and interacts with. I defined our design system in tailwind.config.ts — brand colors, status colors, priority colors — so the whole team uses consistent styling without raw hex values.

I built the main pages: login and registration, the ticket list, ticket detail, and the new-ticket form. I also created TicketStatusControls — buttons that only appear when the user's role is allowed to change status, matching Valza's permission matrix.

Route protection in middleware.ts checks for the access_token cookie before loading protected pages. All API calls go through lib/api.ts with credentials:include so httpOnly cookies are sent automatically.

In Sprint 3 I added the filter bar and search box on the ticket list, connected to Paulina's filtering API."

  • If asked about auth in frontend: We never store JWT in JS — cookies only
  • If asked about middleware: Checks cookie presence; full JWT validation is on backend

🎤 Lis — Speaking Notes 1.5–2 min

"I owned DevOps and QA — making the project runnable, testable, and deployable. I built the Docker Compose stack so all five of us run identical local environments with one command: docker compose up --build. That includes PostgreSQL, MinIO, the FastAPI backend, and the Next.js frontend.

I set up GitHub Actions CI: every pull request runs backend tests with an 80% coverage gate, frontend lint and type-check, and security audits with pip-audit and npm audit. Nothing merges unless CI is green.

For production I deployed to a Contabo VPS with Caddy as reverse proxy for HTTPS, wrote the deploy script, and created seed data for demos. I also implemented resolved_at tracking, audit logs, presigned attachment downloads, and database indexes for performance.

Without this infrastructure layer, the team couldn't develop in parallel safely or demo the project live in production."
  • Demo point: Show docker compose up → seed.py → live app on VPS
  • If asked about CI: 3 jobs — backend, frontend, security — all must pass
  • If asked about deploy: Caddy → app.* frontend, api.* backend, files.* MinIO
